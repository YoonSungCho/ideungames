# 게임 화면 UX 가이드

스도쿠를 만들며 사용자(부모)와 정한 규칙. **새 게임도 이 흐름·배치를 그대로 따른다.**
구현 예시: `src/games/sudoku/`(퍼즐, 시간 기록), `src/games/quick-math/`(스피드, 시간·점수 기록).
공용 게임 부품은 `src/shared/game/` — `StartOverlay`(시작하기·계속하기), `useGameClock`/`useAutoPause`, 메달(`medals.ts`: 시간=lower/점수=higher), 기록(`records.ts`: `addRun`, TOP 10), 기록 화면 스타일(`Records.module.css`).
세 번째 게임에서 또 같은 코드가 보이면 그때 `shared/`로 올린다.

## 1. 게임 한 판의 상태

```
메뉴(모드·난이도 고르기) ─▶ 시작 전(ready) ─[▶ 시작하기]─▶ 진행(playing) ─▶ 클리어(won)
                                              ▲   │ ⏸ / 앱 내림 / 새로고침 / 설정 다녀옴
                                              └─[▶ 계속하기]── 멈춤(paused)
```

- **시간은 "시작하기"를 눌러야 흐른다.** 시작 전·멈춤 중에는 보드를 흐리게 가리고(미리 풀기 방지) 큰 버튼만 보인다.
  → `StartOverlay`, store의 `status: 'ready' | 'playing' | 'won'` + `paused`.
- 멈춤 버튼(⏸)은 타이머 옆. 화면이 숨겨지면(`visibilitychange`) 자동 멈춤. `paused`는 저장하지 않고 기본값 `true`
  → 앱을 다시 열면 진행 중인 판은 멈춘 상태로 시작.

## 2. 나갔다 들어올 때 (가장 많이 틀렸던 부분)

| 나간 방법 | 다시 들어오면 |
|---|---|
| 게임 중 ← / 안드로이드 뒤로 → 확인창 **그만하기** | **메뉴** + 맨 위 [▶ 하던 게임 이어하기] |
| 확인창 **계속하기** | 그 자리에서 그대로 진행 (멈춤 화면 없음) |
| 메뉴나 시작 전 화면에서 나감 | **메뉴** |
| 게임 중 ⚙ 설정 → ← | **게임으로** 돌아와 멈춤 상태 → [계속하기] |
| 게임 중 앱 내림 / 새로고침 | 멈춤 상태 → [계속하기] |
| 클리어 후 나감 | 메뉴 (이어하기 없음) |

- **이어하기는 한 번에 진행된다.** 이어하기 → 다시 "계속하기"를 누르게 하지 않는다.
- 진행 중인 판을 버리는 동작(다른 모드·난이도 고르기)은 `<ConfirmDialog>`로 묻는다. **안전한 쪽(계속하기)을 크게**.
  시작 전(ready)인 판은 버려도 아깝지 않으니 묻지 않는다.
- 설정 화면은 어디서 들어와도 ← 가 **왔던 화면으로** (`<Header backToPrevious>`).
- 허브 연결: `useLeaveGuard(진행중, 그만할때)` — 진행 중이면 나가기 확인창, "그만하기"면 콜백 호출.
  게임 하위 화면(기록 등)과 설정으로 가는 건 확인 없이 허용.

## 3. 화면 배치

### 공통
- **보드 위는 최대 2줄**: ① 허브 상단 바(← · 게임 버튼 · ⚙) ② 상태 한 줄(목표·최고 기록·타이머).
  게임 버튼(모드·난이도)은 `<HeaderSlot>`으로 상단 바 가운데에 넣는다 (게임 중에는 제목 대신 보임).
- 보드(게임판)가 주인공. 남는 공간을 최대한 보드에 준다 (`.boardWrap`이 size 컨테이너, 보드 = `min(100cqw, 100cqh)`).
- 손가락으로 누르는 것: 보드 칸 ≥ 30px, 카드·버튼 ≥ 40~44px.

### 세로 화면 (폰, 폴드 커버)
- 위에서부터: 상단 바 → 상태 줄 → (빈 공간) → 보드 → 도구 → 숫자 카드. 보드·카드는 손가락 가까이 아래쪽.
- 로봇 말풍선은 숨긴다. 높이 860px 미만이면 도구 라벨도 숨긴다.
- 카드가 많으면(9개) 5+4 두 줄, 아랫줄 가운데 정렬 (10칸 그리드에 2칸씩).

### 가로 화면 (폴드 펼침, 폰 가로, 태블릿 가로, PC) — `min-aspect-ratio: 1/1` & `min-width: 560px`
- **왼쪽: 보드가 높이를 꽉 채움 | 오른쪽 칸(`clamp(240px, 30vw, 400px)`): 상태 · 로봇 · 숫자 카드 · 도구.**
- 오른쪽 숫자 카드는 전화 키패드처럼 (4개 → 2×2, 9개 → 3×3).
- 높이 430px 이하(주소창 있는 폰 가로)는 로봇 말풍선 숨김.

## 4. 승부욕 장치 (기록)

- 모드·난이도별 **메달**: 💎 다이아 / 🥇 금 / 🥈 은 / 🥉 동 — 기준 시간 이하로 풀면 획득 (`records.ts`).
- 게임 중 상태 줄에 **"🥇 금 메달까지 0:23" 실시간 카운트다운**, 최고 기록보다 빠르면 최고 기록 숫자가 초록색.
- 클리어 창: 받은 메달, "최고 기록 갱신!(초 단위로 빨라졌을 때만)", "내 기록 N등", "다음 목표: 🥇 0:45 안에".
- 기록 화면(`/games/<id>/records`): 메달 진열장(다이아 n/전체), 다음 메달까지 진행 막대, 빠른 순 TOP 5, 바로 도전 버튼.
- 기록은 TOP 10만 보관 (`runs`). 저장 구조를 바꾸면 persist `version`을 올리고 `migrate`로 옛 기록을 옮긴다.

## 5. 쉬움/도전 모드 (설정)

- 쉬움: 실수 횟수 숨김, 힌트 무제한, 칭찬 위주. 타이머·메달은 보인다.
- 도전: 실수 횟수 표시, 힌트 3번.

## 6. 소리로 읽어 주기 (TTS)

- `speak(text)` (`shared/sound/speak.ts`) — 기기의 한국어 음성. 소리 설정이 꺼져 있으면 조용.
- **듣고 맞히는 문제는 음성이 없을 수 있다**: `useCanSpeakKorean()`이 false면 읽을 말을 글자로 보여준다.
- 문제 안내 글에 정답이 되는 낱말을 적지 않는다 (듣기 문제가 글자 맞추기가 되어 버림).
- 이야기 장면은 말하는 사람별 목소리(`Cutscene`의 `VOICE`): 마왕은 `speak(..., { male: true })`로 기기에 남성 한국어 음성이 있으면 그걸 쓰고, 음높이·속도를 크게 낮춘다.
- 읽어 주는 건 **문제**와 **두 번 틀렸을 때의 정답 안내**뿐. 보기를 누를 때·맞혔을 때는 효과음만 (사용자 요청 — 같은 말을 두 번 듣게 돼 불필요).

## 7. 화면이 여러 단계인 게임 (지도 → 지역 → 단계)

- 라우트로 나누고(`/games/<id>/<region>/play`), 상단 ←는 한 단계 위로 간다(허브가 자동 계산).
- 단계 진행 중엔 같은 게임 안의 다른 화면으로 가도 확인: `useLeaveGuard(진행중, 콜백, true)`.
- 게임 안 이동은 절대 경로로 (`/games/<id>/...`). 중첩 라우트에서 `'..'`는 라우트 기준이라 예상과 다른 곳으로 간다.
- 이야기 장면은 처음 한 번(지역 소개)·매번(보스 등장)을 구분하고, 언제든 `건너뛰기`.

## 7-1. 한글 용사 낱말 사전 (`src/games/hangul-hero/data/`)

- `words.ts` 그림 낱말(무리별, 이모지 13.0까지·그림 중복 없음) → 첫소리·첫 모음 표는 여기서 자동 생성.
- `vocab.ts` 글자로만 읽는 낱말 (무리별). `categories.ts` 무리 21개 — 오답은 **다른 집안(family) + 충돌(conflicts) 없는 무리**에서만
  (예: "음식을 찾아 줘"에 닭이 오답으로 나오면 답이 둘 → food ↔ animal 충돌).
- `sentences.ts` 그림 문장, `opposites.ts` 반대말 짝(같은 group끼리는 오답으로 안 씀).
- 낱말은 한글만, 띄어쓰기 없이, 사전 전체에서 한 번만 — 단위 테스트가 막는다. 새 낱말은 목록에 더하기만 하면 모든 문제에 쓰인다.

## 7-2. 실시간 게임 (숫자 비)

- 매 프레임 바뀌는 판은 저장소에 매번 쓰지 않는다: `game`은 메모리, **멈출 때·끝날 때만 `saved`에 저장**(`pagehide`에서도 멈춤). 다시 열면 `saved`로 멈춘 상태.
- 화면 효과(터짐·번쩍임·알림 글자)는 상태가 아니라 사건(`onGameEvents`)으로 받아 UI가 잠깐 그린다.
- 배경 음악은 진행 중에만(시작 버튼을 누른 뒤라 소리가 막히지 않음), 상단 바 🎵로 끌 수 있고 소리 설정이 꺼지면 조용.

## 7-3. 걸어 다니는 모험 (한글 몬스터)

- 시간 기록이 없는 게임이라 시작하기·멈춤 화면이 없다. 위치·친구·가방은 늘 저장되고, 다시 들어오면 그 자리에서 이어진다.
- 배틀 중에만 나가기 확인. "그만하기"면 배틀은 없던 일로 (체력도 배틀 전 그대로).
- 움직이기: 칸을 누르면 그 칸까지 걸어가고(사람·건물을 누르면 앞까지 가서 말 걸기), 방향 버튼·화살표 키도 된다.
- 지도는 카메라가 따라다니므로 지도 위 사람·건물은 `button`이 아닌 `role="button"` 칸으로 둔다 (화면 밖 검사에서 빠지게).
- 문제는 다른 게임 엔진을 그대로 쓴다: 한글 용사 `makeQuestion`(보기·글자 짓기·문장 순서), 숫자 비 `makeQuestion`·빠른 계산 `generateSet`(숫자·계산), 스도쿠 `generatePuzzle`(상자). 기술 = 문제 유형이라, 여러 속성의 몬스터를 모을수록 여러 가지를 배운다.
- 길을 잃지 않게: 화면 오른쪽 아래 🎯 다음 목표(`nextGoal`), 상단 🗺️ 전체 지도(지역 길·지금 여기·잠긴 곳·작은 지도에 내 위치와 목표).
- 그림: 몬스터는 `ui/looks.ts`의 부품 조합(몸·귀·뿔·꼬리·날개·머리 장식·무늬·눈·입)으로, 지도는 `MapArt`가 칸마다 SVG로 그린다(길·물가는 이웃 칸을 보고 가장자리 처리). 새 몬스터는 species + looks 두 곳에 추가.
- CSS 모듈 안에서 클래스 이름이 겹치면(예: 지도 칸 `.tile`과 낱말 조각 `.tile`) 뒤의 규칙이 덮어쓴다 — 이름을 나눈다.

## 7-4. 자유 놀이 (색칠 놀이)

- 시간·점수가 없는 놀이는 시작하기·멈춤·나가기 확인이 없다. 한 번 누를 때마다 저장되고, 언제 나가도 칠한 그대로.
- 지우는 동작(처음부터)은 `<ConfirmDialog>`로 묻고, 되돌리기로도 살릴 수 있다.
- 다 칠했을 때 축하는 그 그림에서 처음 한 번만 (지웠다 다시 칠해도 또 뜨지 않음).
- 저장(PNG)할 그림은 CSS 모듈 클래스가 아니라 SVG 속성으로만 색을 칠한다 (파일로 옮기면 CSS가 없어진다).
- 붓 그림은 도안 선 **아래**에: 보이는 선만 마스크로 만들어(조각을 아래부터 검은 면 + 흰 테두리로 쌓기) 붓 그림 위에 다시 얹는다.
- 지우개는 아이가 기대하는 대로 **문지르면 지워져야** 한다. 지우개 선은 앞서 그린 붓 선만 마스크로 지우고(칠한 색은 그대로),
  콕 누르면 그 조각의 색을 지운다. 되돌리기로 살릴 수 있다.
- 도안 조각 id는 목록 순서대로 매겨진다 → 새 도안은 **맨 뒤에** 붙인다 (중간에 넣으면 저장된 칠이 엉뚱한 조각으로 간다).

## 7-5. 카드·미로 (짝꿍 카드, 미로 탈출)

- 판 크기에 맞춰 칸을 고른다: 짝꿍 카드는 카드가 가장 커지는 열·행(세로 3×4 ↔ 가로 4×3), 미로는 정사각형을 `min(100cqw, 100cqh)`로.
- 미로 움직임은 한 칸씩 걷는 줄(`walker`)로 — 여러 칸을 한 번에 옮기면 캐릭터가 벽을 뚫는 것처럼 보인다.
- 칸 누르기는 같은 줄·벽 없는 칸까지만 (미로를 대신 풀어 주지 않게). 휙 밀기는 굽은 길을 따라 갈림길까지.
- 미로 조작은 **누르고 있으면 계속 가야** 한다 (한 번 누를 때 한 칸뿐인 방향 버튼은 아이에게 답답하다):
  조이스틱을 밀고 있거나 미로 위를 누른 채 밀고 있으면 손을 뗄 때까지 걷고, 꺾인 길은 알아서 돈다.
  캐릭터를 잡고 끌면 손가락을 따라오되, 곧게 이어진 길만 (벽 너머로 끌면 빙 돌아가지 않는다).
- 카드처럼 누르는 게 전부인 판은 `pointerdown`에 반응하고 `touch-action: none`으로 — `click`은 누르는 사이
  손가락이 조금만 밀려도 화면 끌기로 바뀌어 안 눌린다.
- 둘이서 마주 앉아 하는 대결은 상대 칸(이름·점수·차례)을 화면 위쪽에 **거꾸로** 두고, 열린 카드도 지금 차례인 사람 쪽을 향한다.

## 8. 문구·피드백

- 아이에게: 짧고 다정하게, 이름 부르기 `callName(name)` → "이든아".
- 정답/오답/줄 완성/클리어마다 소리(`playSound`) + 애니메이션 + (가로 화면) 로봇 반응.
- 오답은 혼내지 않는다 ("괜찮아, 다시 해 보자!").
- 두 번 틀리면 정답을 초록색으로 보여주고 **말로도** 안내한다 ("정답은 ㅂ! 초록색을 눌러 볼까?"). 그래도 아이가 직접 눌러야 넘어간다.
- 다음에 할 일을 표시한다 (지역 화면의 "여기부터!").
- 한국어 문구의 조사는 받침에 맞춘다 — 낱말이 바뀌는 자리에 "~가/이"를 붙이지 말고 문장을 바꾼다.
